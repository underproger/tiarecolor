# tiarecolor.ua — вёрстка

Статика: HTML + CSS + чистый JS, без сборщиков и зависимостей. БЭМ-классы, готово к натягиванию на CMS.

```
index.html              главная (SVG-спрайт иконок встроен в начало <body>)
product.html            карточка товара
catalog.html            каталог (категория «Фарба для волосся»)
cart.html               кошик
checkout.html           оформлення замовлення
about.html              про компанію
faq.html                часті питання
contacts.html           контакти
delivery.html           доставка і оплата
returns.html            обмін і повернення
loyalty.html            система лояльності
masters.html            для майстрів (спеціальні умови)
verify.html             верифікація майстра (форма з завантаженням документів)
account*.html           кабінет клієнта: огляд, замовлення, деталі замовлення, обране, особисті дані, адреси
master*.html            кабінет майстра: огляд, замовлення за спец-цінами (+ деталі), обране, реферали, бонуси, статус
assets/css/style.css    все стили: токены → компоненты → секции → адаптив

assets/img/             картинки из макета (2x, webp)
assets/fonts/           Ysabeau Infant (variable, OFL)
```

## Что важно знать

- **Шрифт.** Ysabeau Infant (Google Fonts, OFL), self-hosted variable woff2: один файл на набор символов (cyrillic / latin / latin-ext) покрывает все начертания 1–1000. Межбуквенные интервалы сверены с ширинами строк в макетах. Начертания в макете — только 400, 500 и 700 (600 не используется): жирное — 700, тексты в баннерах, заголовки таблиц и крупные заголовки/цифры баннеров — 500. `<b>`/`<strong>` явно 700, чтобы `bolder` внутри жирного родителя не давал 900.
- **Слово «догляду» в hero** — в макете набрано шрифтом Atziluth (Motokiwo, коммерческий). Пока это SVG, снятый с макета (`assets/img/hero/script-dogliadu.svg`), в `<h1>` попадает через `alt`. Когда будет woff2 с веб-лицензией — заменить на живой текст с `@font-face`.
- **Цифры в таблицах кабинета** — в макете набраны другим (геометрическим) шрифтом; сейчас везде Ysabeau Infant.
- **Hero**: 3 слайда-заглушки с одинаковым контентом (в макете 3 точки).
- **Слайдеры** (hero и товары): бесконечные. Работают на нативной прокрутке со scroll-snap, поэтому на тачах свайп с родной инерцией. JS добавляет копии карточек с обеих сторон (`data-clone`, `aria-hidden`, без фокуса и без дублей `id`/`h1`) и, когда прокрутка останавливается, незаметно переносит позицию на ту же карточку в оригинальном наборе. Мышью ленты можно тянуть (grab) с инерцией и доводкой до карточки; после перетягивания клик по карточке не срабатывает. Текст и картинки в лентах не выделяются. То же перетягивание есть у Instagram-ленты, отзывов и брендов на мобильных, миниатюр и главного фото в карточке товара. Точек = страниц (`ceil(товаров / видимых)`).
- **Баннеры мега-меню** вырезаны из `menu_catalog.jpg` (1x) — для ретины лучше взять исходники.
- **Адаптив** сделан самостоятельно (макета нет): ≤1360, ≤1180, ≤1100 (hero в колонку), ≤1023 (меню в бургер), ≤767, ≤420.
- **Карточка товара**: иконки и фото — из PDF-макета (векторы и исходники 1024px). Вкладки «Характеристики», «Спосіб застосування», «Склад», «Відгуки» — по отдельным макетам. Вкладка «Відгуки» не дублирует отзывы: блок отзывов под табами подтягивается наверх (класс `is-tab`), остальные панели скрываются.
- **Каталог**: фильтры — обычная `<form>` (имена полей `brand`, `volume`, `country` и т.д. — под GET-параметры), группы сворачиваются через нативный `<details>`. Чипы «Обрано» пересобираются из отмеченных фильтров после первого изменения. До 1024px сайдбар уезжает в выезжающую панель (кнопка «Фільтри»).
- **SVG-спрайт** иконок встроен в каждую страницу (оптимизирован svgo, ~40 КБ). При натяжке на CMS лучше вынести его в общий шаблон шапки.
- «Обране» и форма подписки — пока только визуальная реакция; «купити» кладёт товар в мінікошик (см. ниже). Места для интеграции помечены `TODO` в `main.js`.
- **Перелинковка (временная).** Все категории, пункты меню и мега-меню, «Дивитись всі», баннеры, бренды, хлебные крошки и формы поиска ведут на `catalog.html`; карточки товаров — на `product.html`; «Кошик» в шапке — на `cart.html`, «Оформити замовлення» — на `checkout.html`. «Майстрам» в шапке, «Для майстрів» в бургере и заголовок «Майстрам» в футере ведут на `masters.html`, кнопки на ней — на `verify.html`. «Обране» в шапці й бургері веде на `account-favorites.html`. Пока ведут в `#`: Навчання та гайди, Публічна оферта, Політика конфіденційності, Забули пароль — для них нет макетов.
- **Кошик**: у каждой позиции `data-price` (цена) и `data-old` (цена без скидки). При изменении количества и удалении JS пересчитывает суммы по строкам, «Товари (N)», «Знижка майстра», «До сплати» и подпись «N товари» с правильным склонением. Если удалить все позиции — показывается пустое состояние. Промокод пока только визуально (`TODO`).
- **Оформлення**: обычная `<form id="checkout-form">` (поля `first_name`, `last_name`, `phone`, `email`, `delivery`, `payment`, города/отделения), кнопка «Підтвердити замовлення» и чекбокс согласия в правом блоке привязаны к ней через атрибут `form`. Поля неактивного способа доставки отключаются (`disabled`) и не уходят на сервер. Ссылки «Київ / Львів / Одеса / Вінниця» подставляют город в select. Выпадающие списки кастомные (`data-select`): поверх нативного `<select>`, который остаётся в форме и отдаёт значение, `required` и `disabled`. Клавиатура как у нативного (стрелки, Enter, Esc, набор букв), поиск появляется, если пунктов больше 7 (или есть `data-select-search`). Если не хватает места снизу, страница подкручивается. Новые `<option>` (например, отделения из API Нової пошти) и смена значения через `change` подхватываются автоматически. Проверка — нативная валидация браузера, невалидные поля подсвечиваются. Отправка — `TODO` в `main.js`. Списки городов и отделений — заглушки, на проде подтягиваются из API Нової пошти.
- **Правый блок «Ваше замовлення»** липкий (sticky) на десктопе; до 1024px блоки суммы на обеих страницах встают под основной контент.
- **Кабінети** (`account*.html`, `master*.html`): спільний каркас — сайдбар з профілем і меню (на мобільних меню стає горизонтальною стрічкою), контент праворуч. Сторінки мають `noindex`. Іконки кабінету винесені в окремий спрайт, який вбудовується лише в ці сторінки (~15 КБ), щоб не обтяжувати решту сайту.
- **Таблиці кабінету** — справжні `<table>`, рядки виглядають окремими картками; на мобільних (а таблиця майстра — до 1180px) перетворюються на картки з підписами з `data-label`. Фільтр «Усі / Оплачені / Доставлені / Скасовані» працює на клієнті за `data-status` — на проді краще перезавантажувати список з параметром.
- **Демо-логіка кабінету** (місця інтеграції — `TODO` в `main.js`): копіювання реферального посилання, перевірка збігу паролів, вибір основної адреси, відкриття/закриття форми редагування адреси, видалення адреси.
- `master-order.html` (деталі замовлення майстра) окремого макета не має — зібрана за макетом деталей замовлення клієнта, з підсумком «роздріб / спец-ціна».
- **Вхід / реєстрація** — одне модальне вікно `<dialog id="auth">` з вкладками, вбудоване в кожну сторінку (кінець `<body>`). Відкривається будь-яким елементом з `data-auth-open` («Кабінет» у шапці й мобільному меню); `data-auth-open="register"` відкриває одразу реєстрацію (кнопки «Реєстрація» в каталозі та «Зареєструватись» у картці товару). Без JS це звичайні посилання на `account.html`. На сторінках кабінету (`body.page-account`, користувач уже увійшов) модалка не перехоплює кліки. Закривається хрестиком, Esc і кліком по затемненню, фокус тримається всередині (нативний `showModal`). Поки без бекенда кнопки «Увійти» і «Створити акаунт» одразу ведуть у `account.html` (без перевірки полів; `TODO` в `main.js`). «Верифікація» в модалці, «Пройти верифікацію» на головній і «Стати майстром» у кабінеті клієнта ведуть у кабінет майстра `master.html`. «Забули пароль?» — заглушка: макета цього кроку немає.
- **Про компанію** (`about.html`): фото вирізані з макета (`assets/img/about/`). Головне фото в PDF лише 1235 px завширшки, тож на ретіні воно трохи м'якше — краще взяти оригінал. Смуга переваг унизу — той самий блок `.advantages`, що й у каталозі. Посилань на сторінку в макетах шапки й футера немає.
- **Футер**: у нижньому рядку посилання «Про компанію | Доставка і оплата | Обмін і повернення | Контакти | Часті питання» (на десктопі «Публічна оферта | Політика» переносяться на другий рядок), заголовок «Контакти» веде на `contacts.html`.
- **FAQ** (`faq.html`): акордеон на нативних `<details name="faq">` — одночасно відкрите одне питання, працює без JS. Фільтр за темами — `data-cat` у кожного питання (може бути кілька тем через пробіл). Відповіді складені з текстів макетів «Доставка і оплата», «Система лояльності», «Для майстрів» — варто перевірити. Додано розмітку `FAQPage` (JSON-LD) для розширених сніпетів.
- **Контакти** (`contacts.html`): телефон, пошта, месенджери — робочі посилання (`tel:`, `mailto:`, t.me, viber://, wa.me). Форма «Напишіть нам» — перевірка полів і відгук кнопки, відправка — `TODO`. Іконки месенджерів окремим спрайтом лише на цій сторінці. Додано розмітку `Organization` з `ContactPoint` (JSON-LD).
- **Доставка і оплата** (`delivery.html`), **Обмін і повернення** (`returns.html`): спільний шаблон текстової сторінки — секції з іконкою (`.info-section`), іконки окремим спрайтом лише на цих сторінках. Логотип Нової Пошти — растр з макета (`assets/img/about/nova-poshta.webp`). Також на них ведуть: переваги в картці товару (доставка, оплата, повернення), «умови покупки і повернення» в оформленні замовлення, відповідь про доставку в FAQ.
- **Система лояльності** (`loyalty.html`): фон банера — фото з макета без тексту (`assets/img/loyalty/hero.webp`, для мобільних — обрізана версія `hero-m.webp`), заголовок і кнопка — живий текст. На планшетах під текстом банера з'являється світлий градієнт, щоб текст читався поверх монет. На сторінку ведуть: пункт «Бонуси та кешбек за друзів» у смузі переваг (каталог, про компанію, контакти), відповідь про бонуси в FAQ, «Умови програми» в кабінеті майстра.
- **Верифікація майстра** (`verify.html`): звичайна `<form>` з `enctype="multipart/form-data"`, поле файлів `documents[]` (JPG/PNG/PDF, до 10 МБ, до 5 файлів). Файли можна перетягнути або вибрати; вибрані додаються до списку (а не замінюють його), кожен можна прибрати. Невідповідні формат чи розмір відсіюються з повідомленням. Перевірка — нативна валідація; після успішної перевірки зараз перехід на `master-status.html`, відправка — `TODO` в `main.js`. Сторінка має `noindex`. Примітку «(п.8.4 ТЗ)» з макета прибрано — це посилання на ТЗ, не текст для покупців.
- **Плавна прокрутка** — Lenis (`assets/js/vendor/lenis.min.js`, MIT, ~19 КБ). Працює лише для миші/тачпада й вимикається при «зменшенні руху» в системі; на телефонах і планшетах — звичайна нативна прокрутка. Внутрішні прокручувані блоки (бургер, мега-меню, модалки, мінікошик, списки селектів) прокручуються самі по собі. Коли відкрите меню чи модалка — сторінка стоїть. Вимкнути: прибрати підключення `lenis.min.js` — решта коду працює без нього.
- **Бургер-меню** — другий рівень: «Каталог товарів» (групи мега-меню розгортаються всередині), «Готові рішення», «Фарбування», «Стайлінг», «Техніка», «Бренди» відкривають панель із кнопкою «Назад». Решта пунктів — звичайні посилання.
- **Мінікошик** — панель справа: відкривається іконкою «Кошик» у шапці (на `cart.html` і `checkout.html` іконка просто веде на сторінку) і після «купити» на картці чи «Купити» в товарі. Кількість, видалення, сума, смужка до безкоштовної доставки (2000 грн), лічильник у шапці. Поки без бекенда — кошик зберігається в `localStorage` (`tc-cart`), на першому візиті там ті самі 3 товари, що й на `cart.html`; сама `cart.html` лишається статичною. На CMS обидва рендеряться з кошика сайту — `TODO` в `main.js`.
- **Збільшення фото товару** — кнопка-лупа на фото або клік по фото: повноекранний перегляд з гортанням (стрілки, клавіатура, свайп) і мініатюрами. Клік по фото — збільшення ×2.2 з оглядом за курсором; на телефоні — подвійний тап і перетягування.
- **Відгуки**: «Залишити відгук» відкриває форму (оцінка зірками, ім’я, email, текст) з перевіркою полів і екраном подяки; «Відповісти» під відгуком розгортає коротку форму відповіді. Відправка — `TODO` в `main.js`.
- **Кнопка «Нагору»** з’являється після прокрутки на ~1,2 екрана.
- **Обране** (`account-favorites.html`, `master-favorites.html`) — вкладка в обох кабінетах. Сердечко на картці прибирає товар зі списку (з анімацією), «Усе в кошик» кладе всі товари в мінікошик, коли список порожній — заглушка з кнопкою в каталог. Поки список статичний — на CMS береться з обраного користувача (`TODO` в `main.js`). Натиснуте сердечко на всьому сайті тепер залите кольором.
- **Анімації.** Перший екран (hero, заголовки сторінок, картка товару) плавно піднімається при завантаженні — чистий CSS, без мерехтіння. Блоки нижче з’являються при прокрутці, сітки карток, кроки й переваги — по черзі (IntersectionObserver у `main.js`; клас `.rv` ставиться лише тому, що нижче першого екрана, і знімається після появи). Цифри «500+ / 1200+ / 100%» на «Про компанію» набігають від нуля. FAQ, групи в бургері й список товарів в оформленні розгортаються плавно (`::details-content`; у браузерах без підтримки — як раніше). Усе вимикається, якщо в системі ввімкнено «зменшення руху».
